# SlotMate 요구사항 정의서 v0.1

- 작성일: 2026-10-19
- 상태: 초안 — 사용자와 검토 후 확정
- 프로젝트명: SlotMate (가칭)

## 1. 목적 및 범위

피트니스 센터의 PT·요가·GX 프로그램 회차별 예약을 관리하는 웹 서비스다. 예약 가능 인원을 초과하지 않게 처리하며, 만석이면 대기자를 접수하고 확정 예약 취소 시 대기자를 자동 승격한다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| 프로그램 | 반복해서 회차를 개설할 수 있는 PT·요가·GX 등 피트니스 프로그램 |
| 회차(Session) | 특정 날짜와 시간에 열리는 프로그램 한 건 |
| 정원(Capacity) | 회차에서 확정 예약을 받을 수 있는 최대 인원 |
| 확정 예약 | 좌석/참여 자리가 확보된 예약 |
| 대기 예약 | 정원이 찬 경우 순서대로 자리를 기다리는 예약 |
| 활성 예약 | 확정 또는 대기 상태인 예약. 취소 상태는 제외 |
| 자동 승격 | 확정 예약 취소로 자리가 생겼을 때 가장 오래 기다린 대기 예약을 확정 예약으로 변경하는 처리 |

## 3. 사용자 역할

### 3.1 일반 회원
- 회원 가입 및 로그인
- 공개된 프로그램·회차 목록과 회차 상세 조회
- 회차 예약 또는 대기 등록
- 본인의 예약·대기 목록 및 상태 조회
- 예약 취소 또는 대기 취소
- 본인에게 발생한 인앱 알림 조회

### 3.2 관리자
- 프로그램 등록·조회·수정·비활성화
- 회차 등록·조회·수정·예약 오픈·마감·취소
- 회차별 확정 예약자와 대기자 조회
- 회차 정원 변경

## 4. 기능 요구사항

| ID | 요구사항 | 우선순위 | 완료 기준 |
|---|---|---|---|
| FR-001 | 회원 가입 및 로그인 | P0 | 올바른 자격 증명으로 로그인할 수 있고 비밀번호 원문은 저장하지 않음 |
| FR-002 | 역할별 접근 제어 | P0 | 일반 회원이 관리자 API를 호출할 수 없음 |
| FR-003 | 프로그램 목록·상세 조회 | P0 | 비활성 프로그램은 일반 회원에게 신규 예약 대상으로 노출하지 않음 |
| FR-004 | 회차 목록·상세 조회 | P0 | 회차 일시, 정원, 확정 인원, 잔여석, 예약 가능 상태를 표시함 |
| FR-005 | 예약 신청 | P0 | 잔여석이 있으면 확정, 없으면 대기 상태로 생성함 |
| FR-006 | 활성 예약 중복 방지 | P0 | 동일 회원은 동일 회차에 확정·대기 상태의 예약을 두 개 이상 가질 수 없음 |
| FR-007 | 예약 취소 | P0 | 본인의 취소 가능한 예약만 취소할 수 있음 |
| FR-008 | 대기자 자동 승격 | P0 | 확정 예약 취소 시 가장 먼저 대기한 회원 한 명이 확정 상태가 됨 |
| FR-009 | 대기 취소 | P0 | 대기 상태인 회원은 자신의 대기를 취소할 수 있음 |
| FR-010 | 내 예약·대기 조회 | P0 | 로그인 회원의 예약을 상태와 회차 일시 기준으로 조회함 |
| FR-011 | 관리자 프로그램 관리 | P0 | 관리자만 프로그램을 등록·수정·비활성화할 수 있음 |
| FR-012 | 관리자 회차 관리 | P0 | 관리자만 회차를 만들고 오픈·마감·취소할 수 있음 |
| FR-013 | 정원 변경 검증 | P0 | 현재 확정 인원보다 작은 값으로 정원을 낮출 수 없음 |
| FR-014 | 인앱 알림 | P1 | 예약 확정, 대기 등록, 자동 승격, 취소 결과를 알림 목록에서 확인할 수 있음 |
| FR-015 | 예약 상태 이력 | P1 | 예약 생성·확정·대기·취소·승격 이벤트와 발생 시각을 추적할 수 있음 |
| FR-016 | 관리자 회차별 목록 검색 | P1 | 상태별 예약·대기 목록을 페이지 단위로 조회함 |

P0는 첫 번째 완성 버전에 반드시 포함하고, P1은 핵심 흐름과 테스트가 안정화된 뒤 추가한다.

## 5. 업무 규칙

| ID | 규칙 |
|---|---|
| BR-001 | 예약 대상은 프로그램이 아니라 날짜·시간·정원을 가진 회차다. |
| BR-002 | 신규 예약은 회차 상태가 `OPEN`이고 시작 시각 전일 때만 허용한다. |
| BR-003 | `확정 예약 수 < 정원`이면 신청을 확정 처리한다. 그렇지 않으면 대기 순서로 등록한다. |
| BR-004 | 같은 회원은 같은 회차에 `CONFIRMED` 또는 `WAITING` 상태 예약을 하나만 가질 수 있다. 취소된 예약 이력은 보존한다. |
| BR-005 | 예약 취소와 대기자 승격은 하나의 일관된 트랜잭션 흐름으로 처리한다. 처리 도중 실패하면 부분 변경이 남지 않아야 한다. |
| BR-006 | 자동 승격 대상은 같은 회차의 `WAITING` 예약 중 생성 시각이 가장 빠른 항목이다. 생성 시각이 같으면 고유 ID로 순서를 결정한다. |
| BR-007 | 회차가 `OPEN`인 동안 확정 예약이 취소되면 대기자가 있다면 한 명을 자동 승격한다. 회차가 마감·취소된 경우에는 신규 승격하지 않는다. |
| BR-008 | 예약 취소가 끝나면 확정 인원이 정원을 초과할 수 없다. |
| BR-009 | 회원은 다른 회원의 예약을 조회·수정·취소할 수 없다. 관리자는 권한 정책에 따라 전체 회차 예약을 조회할 수 있다. |
| BR-010 | 정원은 1 이상의 정수다. 정원을 낮출 때 현재 확정 인원보다 작게 설정할 수 없다. |
| BR-011 | 회차 시작 시각은 종료 시각보다 빨라야 한다. 과거 회차는 신규 예약을 받지 않는다. |
| BR-012 | 시간은 서버 및 DB에서 일관되게 저장하고, 사용자에게는 한국 시간(Asia/Seoul) 기준으로 표시한다. |
| BR-013 | PT 회차는 기본 정원 1명으로 만들 수 있고, 요가·GX 그룹 회차는 회차별 정원을 별도로 설정한다. 실제 정원은 회차의 `capacity`를 기준으로 판단한다. |

## 6. 상태 정의

### 6.1 회차 상태

- `DRAFT`: 준비 중, 일반 회원에게 예약 대상 미노출
- `OPEN`: 예약 및 대기 신청 가능
- `CLOSED`: 신규 예약·대기 신청 마감
- `CANCELLED`: 회차 취소
- `COMPLETED`: 종료된 회차

### 6.2 예약 상태

- `CONFIRMED`: 예약 확정
- `WAITING`: 대기 중
- `CANCELLED`: 예약 또는 대기 취소

`WAITING → CONFIRMED`는 자동 승격 시에만 허용한다. 취소된 예약 이력은 삭제하지 않고 상태로 보존한다.

## 7. 비기능 요구사항

- NFR-001 보안: 비밀번호는 안전한 해시로 저장하고 인증이 필요한 API를 보호한다.
- NFR-002 권한: 서버 측에서 회원 소유권 및 관리자 권한을 검증한다.
- NFR-003 정합성: 동시에 예약 요청이 들어와도 확정 인원이 정원을 넘지 않아야 한다.
- NFR-004 원자성: 예약 취소와 대기자 승격에 실패가 발생하면 관련 DB 변경은 롤백되어야 한다.
- NFR-005 검증 가능성: 예약/취소/대기 승격 핵심 규칙에 대한 자동화 테스트를 작성한다.
- NFR-006 관측 가능성: 실패한 예약 처리의 원인을 서버 로그에서 추적할 수 있어야 한다. 비밀번호·토큰 등 민감 정보는 로그에 남기지 않는다.
- NFR-007 API 문서화: 주요 API의 요청·응답, 오류 응답 및 인증 요구사항을 문서화한다.
- NFR-008 유지보수성: 컨트롤러, 비즈니스 로직, 데이터 접근 책임을 분리하고 핵심 상태 변경에 단위 테스트를 둔다.

## 8. 오류 상황 및 기대 결과

| 상황 | 기대 결과 |
|---|---|
| 정원이 남아 있을 때 신청 | 예약이 `CONFIRMED`로 생성됨 |
| 만석일 때 신청 | 예약이 `WAITING`으로 생성됨 |
| 동일 회원이 같은 회차에 다시 신청 | 중복 활성 예약으로 거절됨 |
| 본인이 아닌 회원이 예약 취소 | 권한 오류로 거절됨 |
| 회차 마감 이후 신규 신청 | 신청 불가 오류 반환 |
| 확정 예약 취소, 대기자 있음 | 취소 처리 후 대기 1순위가 확정되고 인앱 알림 생성 |
| 확정 예약 취소, 대기자 없음 | 확정 인원이 1 감소하고 빈자리가 남음 |
| 다수 사용자가 마지막 한 자리를 동시에 요청 | 한 명만 확정되고 나머지는 대기 처리됨 |
| 확정 인원보다 작은 정원으로 변경 시도 | 변경 거절, 기존 데이터 유지 |

- 배포 후 주요 예약 흐름을 직접 검증할 수 있음

## 11. 확인이 필요한 설계 결정

1. 프로젝트 대상: PT 1:1 세션과 정원이 있는 요가·GX 그룹 수업 회차를 가정함.
2. 자동 승격: 초안에서는 대기자가 별도로 수락하지 않아도 자동으로 확정하는 방식으로 가정함.
3. 취소 정책: 초안에서는 회차 시작 전까지 회원이 직접 취소할 수 있도록 가정함.
4. 관리자 권한: 초기에는 단일 관리자 역할을 가정함.

이 항목들은 DB/API 설계 전에 함께 검토해 확정한다.
