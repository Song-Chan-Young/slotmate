# SlotMate 화면 설계서 v0.2 — 디자인 방향 반영

- 작성일: 2026-10-19
- 상태: 사용자 선호 반영 초안
- 프로젝트명: SlotMate (가칭)
- 대상: 반응형 웹 서비스
- 이번 버전의 결정: 회원 화면은 수업 목록형과 날짜 선택형을 결합하고, 관리자 화면은 주간 시간표형을 중심으로 설계한다.

## 1. 사용자가 선택한 방향

### 회원 화면
- 참고 방향: 첫 번째 레퍼런스의 단정한 수업 목록과 세 번째 레퍼런스의 간단한 날짜 선택을 결합한다.
- 화면 맨 위에서 날짜를 바꾸고 PT·요가·GX 필터를 선택한다.
- 아래에는 시간순 수업 카드가 표시된다.
- 카드에는 시작 시간, 수업명, 강사, 수업 시간, 정원/잔여석, 상태, 다음 행동 버튼을 넣는다.
- 목록에서 핵심 정보를 확인할 수 있어야 한다. 예약을 위해 매번 상세 화면에 들어갈 필요는 없다.
- 모바일은 카드 목록을 세로로 배치하고, 데스크톱은 가독성을 유지하는 넓은 목록형 레이아웃을 사용한다.

### 관리자 화면
- 참고 방향: 주간 캘린더/시간표형 화면을 사용한다.
- 관리자는 날짜·시간별 수업 현황, 정원, 확정 인원, 대기 인원을 한눈에 확인한다.
- 수업 등록·수정은 별도 폼에서 처리하며, 시간표의 각 수업을 선택해 상세 관리로 이동한다.
- 좁은 화면에서는 주간 그리드를 간단한 날짜별 목록으로 전환한다.

## 2. 시각 디자인 기준

- 전체 분위기: 밝고 깔끔한 배경, 충분한 여백, 읽기 쉬운 글자, 둥근 모서리의 수업 카드.
- 기본 배경: 흰색 또는 아주 옅은 회색 계열.
- 기본 텍스트: 짙은 네이비/차콜 계열.
- 강조색: 예약 가능·확정 등 긍정 상태는 초록 계열, 대기 가능은 주황 계열, 마감·취소는 빨강 또는 회색 계열.
- 색상만으로 상태를 구분하지 않는다. 반드시 `예약 가능`, `대기 신청`, `마감`, `예약 확정`, `대기 중`, `취소` 등의 문구를 함께 보여준다.
- 주요 버튼은 화면에서 가장 눈에 띄는 한 가지 스타일로 통일한다. 비활성 버튼은 비활성 상태임을 색상과 문구로 함께 표현한다.
- 실제 구현 시 외부 레퍼런스의 상표나 화면을 그대로 복제하지 않고, 이 기준을 바탕으로 SlotMate 자체 UI를 만든다.

## 3. 회원용 화면

### M01. 홈 / 오늘의 수업

**목적:** 로그인하자마자 오늘 참여 가능한 수업과 본인의 예약 상태를 확인한다.

**구성 요소**
1. 상단 헤더: SlotMate 로고, `수업 찾기`, `예약 내역`, 알림, 내 계정
2. 인사말과 선택된 날짜
3. 날짜 선택 줄: 오늘을 기본값으로 하고 앞뒤 날짜를 빠르게 바꿀 수 있게 한다.
4. 프로그램 필터: `전체`, `PT`, `요가`, `GX`
5. 시간순 수업 목록
6. 내 예약 요약: 오늘 예약 확정 건과 대기 건을 작게 표시

**수업 카드 필수 정보**
- 시작 시각 및 수업 소요 시간
- 프로그램명 및 강사명
- 정원과 예약 현황(예: `예약 8/10`, `잔여 2명`, `대기 2명`)
- 상태 배지와 주요 버튼

**카드 버튼 규칙**
- 예약 가능: `예약하기`
- 마감 + 대기 허용: `대기 신청`
- 이미 예약 확정: `예약 완료` 또는 `예약 내역 보기`
- 이미 대기 중: `대기 중 · 순번 보기`
- 취소/종료된 회차: 버튼 비활성화 및 사유 표시

### M02. 수업 찾기 / 날짜별 목록

- 경로: `/programs` (화면은 프로그램 목록이지만 기본 정렬 기준은 선택 날짜의 회차 시간순)
- 날짜 선택과 프로그램 필터는 목록 상단에 고정한다.
- 기본 정렬은 시작 시간 오름차순이다.
- 검색은 프로그램명 또는 강사명으로 제한해 구현할 수 있다.
- 결과가 없으면 `선택한 날짜에 등록된 수업이 없습니다`와 날짜 변경 동작을 보여준다.
- 예약 가능한 수업을 과도한 배너나 장식보다 먼저 보여준다.

### M03. 수업 상세

- 수업명, 종류, 강사, 시작/종료 시간, 장소(선택), 설명, 유의 사항
- 확정 인원/정원/잔여석 및 대기 인원
- 주요 행동 버튼은 화면 하단 또는 눈에 잘 띄는 영역에 배치한다.
- 정원·예약 가능 상태는 서버 응답 기준으로 표시한다. 화면에 잔여석이 보인다고 예약 성공을 미리 확정하지 않는다.

### M04. 예약 결과

- 확정: `예약이 확정되었습니다`와 수업 일시, `예약 내역 보기` 버튼
- 대기: `대기 신청이 완료되었습니다`와 현재 대기 순번, 자동 승격 규칙에 대한 간단한 안내
- 실패: 이미 예약함, 수업 마감, 동시에 마지막 좌석이 배정됨, 네트워크 오류 등을 쉬운 문장으로 설명하고 다음 행동을 제안한다.
- 다른 회원의 이름이나 예약 상세는 노출하지 않는다.

### M05. 내 예약

- 상단 필터: `전체`, `예약 확정`, `대기 중`, `취소`
- 카드에는 수업명, 날짜/시간, 강사, 상태, 가능한 경우 취소 버튼을 제공한다.
- 대기 중인 항목은 대기 순번을 분명하게 표시한다.
- 취소 전에는 확인 모달을 표시한다.
- 빈 목록이면 수업 찾기로 이동할 수 있는 링크를 제공한다.

### M06. 알림

- 예약 확정, 대기 신청, 대기 자동 승격, 취소 결과를 최신순으로 표시한다.
- 알림 선택 시 관련 수업 또는 예약 상세로 이동한다.
- 1차 버전은 인앱 알림만 구현한다.

### M07. 로그인 / 회원가입

- 단일 컬럼 폼, 짧고 명확한 라벨, 필드 가까이에 오류 표시
- 로그인 및 회원가입은 핵심 수업 목록보다 시각적으로 과도하게 복잡하지 않게 한다.

## 4. 관리자용 화면

### A01. 관리자 홈

- 왼쪽 메뉴(데스크톱): 대시보드, 수업 관리, 회원, 예약 관리, 설정
- 요약 카드: 오늘 수업 수, 확정 예약 수, 대기 인원, 활성 회원 수
- 아래에는 오늘 시간순 수업 목록과 예약/대기 현황을 표시한다.
- 숫자는 운영 상태를 요약하는 보조 정보이며, 가장 중요한 영역은 수업 시간표다.

### A02. 수업 관리 / 주간 시간표

- 경로: `/admin/sessions`
- 주간 날짜 이동과 `오늘` 버튼을 제공한다.
- 행은 시간, 열은 요일로 구성한다. 각 수업 블록은 프로그램명, 시간, 확정/정원, 대기 인원을 짧게 표시한다.
- 상태는 문구와 색상을 같이 사용한다.
- `수업 등록` 버튼을 상단에 고정한다.
- 수업 블록을 선택하면 상세/수정 화면이나 해당 수업의 예약 관리 화면으로 이동한다.
- 시간표를 사용할 수 없는 작은 화면에서는 같은 정보를 날짜별 목록으로 표시한다.

### A03. 수업 등록 / 수정

- 필수 입력: 프로그램, 날짜, 시작 시각, 종료 시각, 정원, 예약 상태
- 선택 입력: 강사, 장소, 설명
- 종료 시각이 시작 시각보다 빠르거나 정원이 1 미만이면 저장하지 않고 필드 옆에 오류를 표시한다.
- 확정 예약 인원보다 정원을 낮추는 변경은 거절한다.
- 이미 예약자가 있는 회차의 일시 변경이나 취소에는 확인 단계를 둔다.

### A04. 회차별 예약 관리

- 상단 요약: 날짜/시간, 정원, 확정 인원, 잔여석, 대기 인원
- `예약 확정`, `대기 중`, `취소` 필터
- 대기 목록은 대기 등록 시각이 빠른 순서로 보여준다.
- 자동 승격 여부와 시간은 결과로 확인할 수 있어야 한다.
- 1차 버전은 관리자의 대기 순서 임의 변경이나 예약 강제 승격을 제공하지 않는다.

### A05. 회원 관리

- 이름/이메일 검색, 계정 상태, 가입 시점 등 운영상 필요한 최소 정보
- 비밀번호, 인증 토큰 등 민감한 정보를 표시하지 않는다.
- 회원 관리 기능은 예약 핵심 흐름이 완성된 이후 우선순위에 따라 구현한다.

## 5. 반응형 규칙

- 넓은 데스크톱: 헤더 + 중앙 콘텐츠, 수업 목록은 넉넉한 가로 폭을 사용한다.
- 태블릿: 필터 줄이 여러 줄로 접힐 수 있고, 수업 카드는 한 줄 또는 한 열로 바뀐다.
- 모바일: 날짜 선택은 가로 스크롤, 필터는 짧은 칩 형태, 카드 버튼은 터치하기 쉬운 크기로 제공한다.
- 관리자 주간 그리드는 모바일에서 날짜별 목록으로 바꾼다.
- 작은 글씨와 가로로 긴 표를 회원 메인 화면에 사용하지 않는다.

## 6. 사용자 흐름

### 자리 있는 수업 예약
1. 회원이 오늘의 수업 또는 수업 찾기에 들어간다.
2. 날짜와 PT/요가/GX 필터를 선택한다.
3. 카드의 시간·잔여석을 확인하고 `예약하기`를 누른다.
4. 서버가 정원, 중복 예약, 회차 상태를 검증한다.
5. 확정 결과를 표시하고 내 예약에 반영한다.

### 만석 수업 대기
1. 만석인 카드에 `대기 신청`이 표시된다.
2. 회원이 신청한다.
3. 서버가 대기 예약을 등록하고 순번을 계산한다.
4. 화면에 `대기 중 · 2번째`처럼 결과를 보여준다.
5. 앞선 확정 예약이 취소되어 승격되면 인앱 알림을 생성한다.

### 관리자 수업 개설
1. 관리자가 주간 시간표에서 `수업 등록`을 선택한다.
2. 프로그램·강사·날짜·시각·정원을 입력한다.
3. 유효성 검사를 통과하면 초안 또는 예약 오픈 상태로 저장한다.
4. 오픈된 수업은 회원용 날짜별 목록에 나타난다.

## 7. 화면 설계 검토 체크리스트

- [ ] 회원은 날짜와 PT/요가/GX 필터만으로 원하는 수업을 찾을 수 있는가?
- [ ] 수업 카드 하나만 보고 시간, 강사, 정원, 잔여석, 다음 동작을 알 수 있는가?
- [ ] `예약 가능`, `대기 신청`, `마감`, `예약 완료`, `대기 중` 상태가 문구로도 명확한가?
- [ ] 휴대폰에서 카드 버튼을 누르기 쉽고 정보가 과도하게 빽빽하지 않은가?
- [ ] 관리자는 주간 시간표에서 수업과 정원 현황을 쉽게 파악할 수 있는가?
- [ ] 관리자 시간표가 작은 화면에서 날짜별 목록으로 전환되는가?
- [ ] 로딩, 빈 목록, 오류, 중복 예약 상황에서 다음 행동이 안내되는가?
- [ ] 화면은 서버가 반환한 예약 결과를 그대로 반영하는가?

화면 방향을 반영했으므로 다음은 API 명세서다. 회원용 수업 목록 조회, 예약/대기 신청, 예약 취소, 내 예약 조회, 관리자 수업 등록·수정 및 예약자 조회에 대해 HTTP 메서드, URL, 요청·응답, 오류 코드와 권한을 정의한다.
