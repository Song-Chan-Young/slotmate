# SlotMate 개발 단계 및 완료 기준

## 단계 1 — 요구사항 확정
- 서비스 대상과 핵심 시나리오 확정
- 기능 우선순위 및 상태 전이 확정
- 완료 기준: 요구사항 v1.0 승인

## 단계 2 — 설계
- 화면 흐름 및 화면 목록
- ERD 및 테이블 정의서 (PT·요가·GX 시간표, 회원 예약, 대기, 상태 이력, 알림)
- 상태 전이도
- REST API 명세서
- 완료 기준: 각 P0 요구사항이 화면/API/DB에 연결되어 있음

## 단계 3 — 개발 환경 및 프로젝트 초기화
- IntelliJ에서 Spring Boot 프로젝트 생성
- GitHub 저장소 연결
- Gradle Wrapper 및 `.gitignore` 확인
- MariaDB 연결, 로컬 환경 설정
- 완료 기준: Windows와 macOS 양쪽에서 같은 브랜치를 받아 실행할 수 있음

## 단계 4 — 기본 기능
- 회원 인증 및 권한
- 프로그램/회차 관리
- 조회 및 예약 생성
- 예약·대기 목록
- 완료 기준: 주요 API를 Swagger UI 또는 API 클라이언트로 확인 가능

## 단계 5 — 핵심 정합성 로직
- 예약 중복 방지
- 동시 예약 시 정원 초과 방지
- 예약 취소와 대기자 자동 승격
- 알림 및 상태 이력
- 완료 기준: 경계 상황과 동시 요청 관련 자동화 테스트 통과

## 단계 6 — 품질·성능·배포
- 검증/예외 응답 통일
- SQL 확인과 필요한 인덱스 추가
- 로그 및 보안 설정
- Docker 및 테스트/배포 자동화는 현재 역량에 맞춰 단계적으로 도입
- README, API 문서, ERD, 테스트 결과, 트러블슈팅 기록
- 완료 기준: 공개 가능한 데모와 기술 의사결정을 설명할 수 있는 문서가 있음

## 개발 원칙
- 모든 기술을 한꺼번에 넣지 않는다.
- 측정하지 않은 성능 개선 수치를 만들지 않는다.
- AI가 생성한 코드는 동작 이유를 이해하고 테스트한 뒤 반영한다.
- 회사 코드나 업무 데이터를 개인 프로젝트 저장소로 옮기지 않는다.
