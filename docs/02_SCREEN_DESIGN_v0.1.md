# SlotMate 화면 설계서 v0.1

- 작성일: 2026-10-19
- 상태: 초안 — 요구사항 및 화면 흐름 검토용
- 프로젝트명: SlotMate (가칭)
- 대상: 반응형 웹 서비스

## 1. 화면 설계 원칙

1. 처음 사용하는 회원도 프로그램을 찾고 예약할 수 있어야 한다.
2. 정원, 예약 가능 여부, 내 예약 상태를 명확히 보여준다.
3. 버튼을 누른 결과를 토스트 문구뿐 아니라 상태 변화로 확인할 수 있게 한다.
4. 예약이 실패했을 때 이유와 다음 행동을 함께 안내한다.
5. 관리자 화면은 예약 확정 인원과 대기 인원, 회차 상태를 빠르게 확인하는 데 집중한다.
6. 이번 버전은 모바일에서도 사용할 수 있는 반응형 웹을 목표로 하되, 우선 데스크톱 화면을 기준으로 설계한다.

## 2. 사이트맵

### 공통/회원

- 로그인 `/login`
- 회원가입 `/signup`
- 프로그램 목록 `/programs`
- 프로그램 상세 `/programs/{programId}`
- 내 예약 `/my/reservations`
- 알림 `/my/notifications`
- 내 정보/로그아웃: 1차 버전에서는 단순 계정 메뉴로 제공

### 관리자

- 관리자 홈 `/admin`
- 프로그램 관리 `/admin/programs`
- 프로그램 등록/수정 `/admin/programs/new`, `/admin/programs/{programId}/edit`
- 회차 관리 `/admin/sessions`
- 회차 등록/수정 `/admin/sessions/new`, `/admin/sessions/{sessionId}/edit`
- 회차별 예약·대기자 관리 `/admin/sessions/{sessionId}/reservations`

관리자 화면은 `ADMIN` 권한이 있는 사용자만 진입할 수 있다. 메뉴를 숨기는 것만으로 보안을 처리하지 않고, 서버에서도 권한을 검증한다.

## 3. 공통 레이아웃

### 상단 헤더

- 좌측: SlotMate 로고 → 프로그램 목록으로 이동
- 중앙/메뉴: 프로그램 보기, 내 예약
- 우측: 알림 아이콘(읽지 않은 알림 수), 로그인 사용자 메뉴
- 관리자 로그인 시: 관리자 메뉴 링크 추가
- 비로그인 상태: 로그인 / 회원가입 버튼 표시

### 공통 상태 표시

- 성공: 작업이 완료되었음을 안내
- 입력 오류: 잘못된 입력 필드 바로 아래에 표시
- 서버/네트워크 오류: 다시 시도할 수 있음을 안내
- 빈 목록: 데이터가 없다는 사실과 다음 행동(프로그램 둘러보기 등)을 표시
- 로딩: 중복 클릭을 방지하고 처리 중임을 표시

## 4. 회원 화면

## P01. 로그인

- 경로: `/login`
- 목적: 기존 회원 인증
- 주요 요소:
  - 이메일 입력
  - 비밀번호 입력
  - 로그인 버튼
  - 회원가입 이동 링크
- 동작:
  - 필수값 누락 시 해당 입력란 아래 오류 표시
  - 인증 실패 시 이메일/비밀번호 중 어느 값이 틀렸는지 특정하지 않고 일반 오류 메시지 표시
  - 로그인 성공 시 원래 접근하려던 화면이 있으면 해당 화면으로, 아니면 프로그램 목록으로 이동
- 예외/상태:
  - 잘못된 인증 정보
  - 서버 오류
  - 로그인 처리 중 버튼 비활성화

간단 와이어프레임:

```text
┌──────────────────────────────────────────┐
│ SlotMate                                 │
│                                          │
│                 로그인                   │
│  이메일       [______________________]   │
│  비밀번호     [______________________]   │
│                [       로그인       ]    │
│            계정이 없으신가요? 회원가입   │
└──────────────────────────────────────────┘
```

## P02. 회원가입

- 경로: `/signup`
- 목적: 일반 회원 계정 생성
- 주요 요소: 이름, 이메일, 비밀번호, 비밀번호 확인, 회원가입 버튼
- 검증:
  - 필수 입력값 확인
  - 이메일 형식 확인
  - 비밀번호 정책 확인
  - 비밀번호와 확인값 일치 확인
  - 이미 가입된 이메일은 중복 오류 안내
- 보안 기준: 비밀번호는 평문으로 저장하지 않고 안전한 해시로 저장한다.

## P03. 프로그램 목록

- 경로: `/programs`
- 목적: 예약 가능한 PT·요가·GX 프로그램을 찾고 회차 상세로 진입
- 주요 요소:
  - PT·요가·GX 프로그램 카드 목록
  - 프로그램명, 종류(PT/요가/GX), 짧은 설명, 기본 수업 시간(옵션)
  - 검색 입력 및 카테고리 필터는 초기 버전에서 제외하거나 최소 구현
  - 카드의 상세 보기 버튼
- 동작:
  - 공개/활성 프로그램만 노출
  - 카드 선택 시 프로그램 상세로 이동
  - 결과가 없으면 빈 상태 문구 표시
- 정렬: 우선 최신 등록순. 별도 정렬 기능은 1차 버전에서 제외 가능

```text
┌─────────────────────────────────────────────────────────┐
│ SlotMate       프로그램 보기  내 예약  알림  계정        │
├─────────────────────────────────────────────────────────┤
│ 프로그램 둘러보기                                       │
│ [프로그램 검색________________] [검색]                  │
│ ┌────────────────┐ ┌────────────────┐ ┌──────────────┐ │
│ │ 프로그램 이름  │ │ 프로그램 이름  │ │ 프로그램명   │ │
│ │ 짧은 설명      │ │ 짧은 설명      │ │ 짧은 설명    │ │
│ │ [상세 보기]    │ │ [상세 보기]    │ │ [상세 보기]  │ │
│ └────────────────┘ └────────────────┘ └──────────────┘ │
└─────────────────────────────────────────────────────────┘
```

## P04. 프로그램 상세 및 회차 선택

- 경로: `/programs/{programId}`
- 목적: 프로그램 정보를 보고 원하는 일시의 회차를 선택
- 주요 요소:
  - 프로그램명, 종류(PT/요가/GX), 설명, 담당 강사, 유의사항
  - 회차별 시작/종료 시각 및 담당 강사
  - 정원(PT는 기본 1명, 그룹 수업은 회차별 설정), 확정 인원, 잔여석
  - 회차 상태(예약 가능, 마감, 취소, 종료)
  - 회차별 예약/대기 버튼
- 버튼 규칙:
  - 비로그인 상태: 로그인 화면으로 안내
  - `OPEN` + 잔여석 있음: `예약하기`
  - `OPEN` + 잔여석 없음: `대기 신청`
  - `CLOSED`, `CANCELLED`, `COMPLETED` 또는 시작 시각 경과: 신청 버튼 비활성화 및 이유 표시
  - 이미 같은 회차에 활성 예약이 있으면 `내 예약 보기`를 제공하고 신규 신청 금지
- 예약 신청 후 서버의 결과를 기준으로 확정/대기 결과를 표시한다. 화면의 잔여석 정보만으로 확정을 보장하지 않는다.

```text
┌─────────────────────────────────────────────────────────┐
│ 프로그램명                                              │
│ 프로그램 설명 / 장소 / 유의사항                         │
├─────────────────────────────────────────────────────────┤
│ 날짜/시간       정원    확정    잔여    상태    동작     │
│ 11/10 14:00     10      7       3      예약 가능 [예약]  │
│ 11/12 14:00     10      10      0      마감      [대기]  │
│ 11/15 14:00     10       -      -      취소      신청불가 │
└─────────────────────────────────────────────────────────┘
```

## P05. 예약 처리 결과

- 표현 방식: 프로그램 상세 화면 내 결과 영역 또는 결과 모달. 별도 URL은 필수 아님
- 성공 결과:
  - 확정: “예약이 확정되었습니다.” + 회차 일시 + 내 예약 보기
  - 대기: “대기 신청이 완료되었습니다.” + 현재 대기 순번 + 내 예약 보기
  - 취소: “예약이 취소되었습니다.” + 대기자 승격 여부를 안내할 수 있으나 다른 회원 개인정보는 표시하지 않음
- 실패 결과:
  - 이미 활성 예약이 있음
  - 예약 마감 또는 회차 시작으로 신청할 수 없음
  - 동시에 다른 회원이 마지막 좌석을 확보함
  - 일시적 서버 오류
- 서버 결과를 다시 조회해 최종 예약 상태를 확인한다. 클라이언트에서 성공 상태를 임의로 만들지 않는다.

## P06. 내 예약

- 경로: `/my/reservations`
- 목적: 로그인한 회원이 자신의 확정·대기·취소 내역을 확인
- 탭/필터:
  - 전체
  - 확정
  - 대기
  - 취소
- 목록 정보:
  - 프로그램명
  - 회차 일시
  - 상태
  - 대기 중인 경우 대기 순번
  - 예약 생성 시각
  - 가능한 경우 취소 버튼
- 취소 동작:
  - 취소 확인 대화상자 표시
  - 확인 후 서버 처리 결과를 반영
  - 확정 예약 취소로 대기자가 승격되면 본인 예약 취소 완료만 알리고 다른 회원 이름은 노출하지 않음
- 취소 버튼은 회차 정책상 취소 가능할 때만 표시한다.
- 빈 목록에는 프로그램 둘러보기 링크를 제공한다.

## P07. 알림 목록

- 경로: `/my/notifications`
- 우선순위: P1
- 목적: 예약 확정, 대기 등록, 대기 승격, 취소 결과 알림 확인
- 주요 요소: 알림 제목, 내용, 발생 시각, 읽음 여부
- 클릭 시 관련 예약 또는 회차로 이동
- 초기 구현은 인앱 알림만 제공하며 이메일/SMS/카카오 알림톡은 제외

## 5. 관리자 화면

## A01. 관리자 홈

- 경로: `/admin`
- 목적: 운영 중인 프로그램과 가까운 회차를 빠르게 확인
- 주요 정보:
  - 활성 프로그램 수
  - 예약 오픈된 회차 수
  - 오늘/임박 회차 목록
  - 관리자용 바로가기(프로그램 관리, 회차 관리)
- 범위 조정: 개발 시간이 부족하면 대시보드 지표는 생략하고 회차 관리 화면으로 바로 진입해도 된다.

## A02. 프로그램 관리 목록

- 경로: `/admin/programs`
- 목적: 프로그램 검색 및 관리
- 주요 요소: 프로그램명, 활성 여부, 등록일, 수정 버튼, 비활성화 버튼, 프로그램 등록 버튼
- 동작:
  - 등록 버튼 → 프로그램 등록 화면
  - 수정 버튼 → 프로그램 수정 화면
  - 비활성화 전 확인
  - 비활성 프로그램에 연결된 과거 예약 기록은 삭제하지 않음
- 검색/페이징은 데이터가 늘어날 때 확장할 수 있으나 기본 목록 조회는 필요

## A03. 프로그램 등록/수정

- 경로: `/admin/programs/new`, `/admin/programs/{programId}/edit`
- 주요 입력: 프로그램명, 프로그램 종류(PT/요가/GX 등), 설명, 기본 수업 시간, 기본 정원, 활성 여부
- 검증: 프로그램명 필수, 길이 제한, 필드별 오류 메시지
- 저장 성공 시 프로그램 목록으로 돌아가고 성공 메시지 표시
- 실제 프로그램 데이터의 형식과 길이 제약은 DB 설계 단계에서 확정

## A04. 회차 관리 목록

- 경로: `/admin/sessions`
- 목적: 회차 등록, 예약 오픈/마감 및 진행 상태 관리
- 주요 정보:
  - 프로그램명
  - 시작/종료 일시
  - 정원
  - 확정 인원/대기 인원
  - 회차 상태
- 주요 동작:
  - 회차 등록/수정
  - `DRAFT → OPEN` 오픈
  - `OPEN → CLOSED` 마감
  - 정책상 가능한 경우 회차 취소
  - 예약·대기자 관리 화면 진입
- 검증:
  - 종료 시각은 시작 시각보다 늦어야 함
  - 정원은 1 이상
  - 확정 예약 인원보다 작은 정원으로 변경 불가
  - 오픈 조건을 만족하지 않으면 오류 이유 안내

## A05. 회차 등록/수정

- 경로: `/admin/sessions/new`, `/admin/sessions/{sessionId}/edit`
- 입력 항목: 프로그램, 시작 일시, 종료 일시, 정원, 상태(상태 변경은 별도 동작으로 구현 가능)
- 등록 기본 상태: `DRAFT`
- 시간대: 화면 입력과 표시는 한국 시간(Asia/Seoul) 기준
- 수정 제한: 이미 예약자가 있는 회차의 일시 변경 등 민감한 수정은 초기 버전에서 제한하거나 확인 단계를 둔다.

## A06. 회차별 예약·대기자 관리

- 경로: `/admin/sessions/{sessionId}/reservations`
- 목적: 관리자에게 회차의 수용 상태 및 예약 상태를 보여줌
- 상단 요약:
  - 회차명 및 일시
  - 정원 / 확정 인원 / 잔여석 / 대기 인원
- 목록 구분:
  - 확정 예약자: 회원 식별에 필요한 최소 정보, 예약 시각, 상태
  - 대기자: 대기 순번, 최소 회원 정보, 대기 등록 시각
  - 취소 내역은 별도 필터로 조회 가능(P1)
- 관리자 액션:
  - 목록 조회 및 페이지 이동
  - 초기 버전에서는 관리자의 임의 예약 확정/대기 순서 변경 기능을 제공하지 않음
- 대기 승격은 시스템 규칙으로 처리하고, 관리자 화면에서는 결과를 확인하도록 한다.

## 6. 핵심 사용자 흐름

### 흐름 A — 자리가 있는 회차 예약

1. 회원이 프로그램 목록에 진입한다.
2. 프로그램 상세에서 회차와 잔여석을 확인한다.
3. `예약하기`를 선택한다.
4. 서버가 권한, 회차 상태, 중복 예약, 잔여 정원을 검증한다.
5. 성공 시 확정 예약 상태를 보여주고 내 예약 목록에 표시한다.

### 흐름 B — 만석 회차 대기 등록

1. 회원이 만석 회차의 `대기 신청`을 선택한다.
2. 서버가 동일 회차의 활성 예약 여부를 확인한다.
3. 중복이 아니면 대기 예약을 생성한다.
4. 결과 화면과 내 예약에 대기 순번을 표시한다.

### 흐름 C — 확정 예약 취소 및 자동 승격

1. 회원이 내 예약에서 취소를 선택한다.
2. 확인 대화상자에서 취소를 확정한다.
3. 서버는 트랜잭션 내에서 취소 처리와 대기 1순위 승격을 수행한다.
4. 실패 시 관련 DB 변경을 롤백한다.
5. 회원에게 취소 결과를 표시하고, 승격된 회원에게 인앱 알림을 생성한다.

### 흐름 D — 관리자의 회차 오픈

1. 관리자가 프로그램을 등록한다.
2. 해당 프로그램의 회차를 등록한다.
3. 일시와 정원을 검증한다.
4. 예약 오픈을 실행한다.
5. 회차가 `OPEN`으로 변경되고 회원 프로그램 상세 화면에 노출된다.

## 8. 1차 버전 구현 우선순위

### P0 — 화면 필수

1. 로그인 / 회원가입
2. 프로그램 목록 / 프로그램 상세 및 회차 선택
3. 내 예약
4. 관리자 프로그램 관리
5. 관리자 회차 관리
6. 회차별 예약·대기자 관리

### P1 — 핵심 예약 흐름 안정화 후

1. 인앱 알림 목록
2. 관리자 홈 통계
3. 목록 검색, 필터, 페이징 고도화
4. 취소 이력 상세 확인

## 9. 화면 설계 검토 체크리스트

- [ ] 프로그램을 비로그인 상태에서 조회할 수 있는가?
- [ ] 예약/대기 상태와 잔여석을 쉽게 구분할 수 있는가?
- [ ] 이미 활성 예약이 있을 때 중복 신청을 막고 안내하는가?
- [ ] 마지막 좌석이 거의 동시에 신청될 때 서버 처리 결과가 정확히 반영되는가?
- [ ] 확정 예약 취소 후 대기자가 자동 승격된다는 규칙이 일관적인가?
- [ ] 회차 마감/취소 시 예약 버튼이 비활성화되고 이유가 표시되는가?
- [ ] 회원에게 다른 사람의 예약·연락처 정보가 노출되지 않는가?
- [ ] 관리자 전용 기능을 서버에서도 권한 검증하는가?
- [ ] 오류·로딩·빈 목록 상태가 모두 정의되어 있는가?

## 10. 이후 확정할 사항

1. 프로그램에 장소 필드가 필수인지 선택인지
2. 관리자가 회원 예약을 대신 등록할 수 있어야 하는지
3. 회차 취소 시 이미 확정된 예약과 대기 예약을 어떤 상태로 전환할지
4. 대기 승격 대상자에게 알림만 제공할지, 일정 시간 내 수락을 요구할지
5. 예약 취소 마감 시각을 회차 시작 전까지로 할지 별도 설정으로 둘지

이 항목은 화면/DB/API 설계를 지나치게 복잡하게 만들지 않도록 초기에는 단순한 정책을 적용하고, 테스트 작성 전에 확정한다.


## 7. 피트니스 프로그램 특화 화면 규칙

- 프로그램 목록은 PT, 요가, GX 등 프로그램 종류를 표시한다.
- 회차는 실제 예약 대상이며, 프로그램 상세에서 날짜·시각별로 여러 회차를 보여준다.
- 회차별로 담당 강사, 시작/종료 시각, 정원, 확정 인원, 잔여석을 표시한다.
- PT는 보통 정원 1명으로 설정하지만, 서버는 하드코딩하지 않고 회차의 정원 값을 기준으로 처리한다.
- 요가/GX도 프로그램 자체에 정원을 고정하지 않는다. 같은 프로그램의 각 회차가 서로 다른 정원을 가질 수 있다.
