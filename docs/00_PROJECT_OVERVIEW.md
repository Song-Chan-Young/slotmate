# SlotMate 프로젝트 개요서

- 문서 버전: 0.1
- 상태: 초안
- 프로젝트명: SlotMate (가칭)
- 유형: 예약·대기 관리 웹 서비스

## 1. 문제 정의

피트니스 센터의 개인 PT와 요가·GX 같은 그룹 수업은 시간대별 정원이 정해져 있습니다. 예약이 마감되면 추가 회원을 받기 어렵고, 기존 예약이 취소돼도 담당자가 대기자에게 직접 연락해야 하는 경우가 있습니다. 이 과정에서 대기 순서가 어긋나거나 정원보다 많은 예약이 접수될 수 있습니다.

SlotMate는 PT·요가·GX 프로그램의 시간표와 회차별 정원을 관리합니다. 회원 예약과 대기 등록을 처리하고, 확정 예약 취소 시 가장 먼저 대기한 회원을 자동으로 예약 확정 상태로 승격합니다.

## 2. 대상 사용자

### 일반 회원
- PT·요가·GX 프로그램과 날짜별 시간표를 조회합니다.
- 자리가 있으면 예약하고, 만석이면 대기 등록합니다.
- 본인의 예약·대기 내역을 확인하고 취소합니다.
- 예약 상태가 바뀌면 서비스 안에서 알림을 확인합니다.

### 관리자
- 프로그램과 수업 회차(일시·강사·정원)를 등록·수정·마감합니다.
- 회차별 정원과 예약자·대기자 목록을 확인합니다.
- 잘못된 정원 변경이나 마감 이후의 신규 예약을 방지합니다.

## 3. 핵심 사용자 흐름

1. 관리자가 프로그램과 회차(일시·정원)를 등록하고 예약을 엽니다.
2. 회원이 회차를 선택해 예약을 요청합니다.
3. 잔여 좌석이 있으면 예약이 확정되고, 만석이면 대기 순서에 추가됩니다.
4. 확정 예약자가 예약을 취소하면, 해당 회차가 예약 가능한 상태인 경우 가장 먼저 대기한 회원이 자동으로 예약 확정됩니다.
5. 승격된 회원에게 인앱 알림이 생성됩니다.

## 4. 차별화 포인트

기본적인 등록·조회·수정·삭제보다 예약 도메인의 무결성에 집중합니다.

- 동시 요청으로 정원을 초과하는 예약이 발생하지 않게 처리합니다.
- 한 회원이 동일 회차에 활성 예약을 중복으로 만들지 못하게 합니다.
- 예약 취소와 대기자 승격을 원자적으로 처리해 중간 상태가 남지 않게 합니다.
- 상태 전이와 경계 상황을 통합 테스트로 검증합니다.
- 실제 측정한 테스트 결과와 성능 개선 내용을 README에 기록합니다.

## 5. 1차 버전에 포함하지 않는 항목

- 실제 결제
- SMS/카카오 알림톡/이메일 발송
- 외부 캘린더 연동
- 복잡한 좌석 선택 및 가격 정책
- 여러 사업자가 입점하는 멀티테넌트 구조
- 마이크로서비스, Kafka 등 꼭 필요하지 않은 분산 시스템

## 6. 기술 방향

초기에는 모듈을 과도하게 쪼개지 않은 단일 Spring Boot 애플리케이션으로 개발합니다. 예약과 대기 관련 핵심 로직을 서비스 계층에 모으고, 트랜잭션·DB 잠금·제약 조건·테스트를 통해 정합성을 검증합니다.
